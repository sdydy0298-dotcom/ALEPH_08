# T08 PRIVATE 정보 관리 · 구현 및 검증 기록

검증 기준: 2026-10-09 · `ALEPH_08` 저장소 · `aleph_common.t08`

## 구현 범위

- 기존 T01 공개 페이지와 T08 패스키 인증 유지
- 로그인한 계정만 `/info.html` 화면 및 `/api/info` 서버 데이터 사용
- 전화번호·상세 주소·생년월일은 전부 **초기값 없이 시작**하며 사용자가 입력할 때만 DB 저장
- 빈 값으로 기본 항목을 저장하면 해당 DB 행 삭제
- 사용자 정의 항목은 이름/내용을 자유롭게 등록·수정·삭제할 수 있으며 내용은 비워도 됨
- `프로젝트 메모`는 화면의 항목명 예시일 뿐 DB에 자동 생성하지 않음
- 기존 패스키, 계정, 기존 비공개 기록 데이터 유지
- 브라우저 소스에 개인 기록·전화번호·주소·생년월일을 하드코딩하지 않음

## 설계

- Front: `info.html`, `info.css`, `info.js`
- Gateway: `api/info.js` → `api/_proxy.js`
- Backend: `supabase/functions/t08-passkey/index.ts` (route=info)
- Data: `t08.private_fields` (`user_id`, `kind`, `label`, `value`, 작성/변경 시각)
- 권한: 서버가 검증한 세션의 `user_id`로 조회, 수정, 삭제 대상 제한. 소유자 ID는 클라이언트에서 받지 않음
- 보호: 전용 비공개 스키마, RLS ON, anon/authenticated 직접 테이블 SELECT/INSERT 권한 없음

## 테스트 권장 순서

1. 기존 패스키로 로그인하고 `/info.html` 진입
2. 기본 항목 3개가 모두 비어 있는 상태 확인
3. 가상의 전화번호 한 건 저장 → 새로고침 → 저장 확인 → 입력값 비우고 저장 → 제거 확인
4. `프로젝트 메모` (내용 빈 값) 항목 추가 → 수정 → 삭제
5. `/private.html` 보관함과 `/records.html` 기존 기록 정상 유지 확인
6. 별도 계정에서 다른 계정의 정보가 나타나지 않는지, 요청값 변조 시 404 거절되는지 확인

테스트 시 실제 전화번호·주소·생년월일을 입력하지 말고 가상 값을 사용한다.
