> 제출 URL: https://sdy-task08.vercel.app/ · 소스: https://github.com/sdydy0298-dotcom/ALEPH_08

## ① 무엇으로 붙였나 (C48)

- 인증 방식: WebAuthn 기반 패스키(비밀번호 사용하지 않음).
- 라이브러리: `@simplewebauthn/browser@13.2.2`, `@simplewebauthn/server@13.2.2`.
- 서버: Vercel Functions → Supabase Edge Functions → PostgreSQL `aleph_common.t08`.
- 프런트는 인증기 요청을 시작하고, 서버가 challenge 및 공개키와 서명 검증을 담당한다.
- 개인키는 기기에 남는다. 서버에 저장하는 값은 credential ID, 공개키, 서명 카운터, 이름, 등록일이다.
- 패스키 저장 위치(Windows Hello/Google 비밀번호 관리자/보안 키)는 실제 등록한 기기에서 확인하여 최종 제출문에 기록한다.

## ② 왜 그걸 골랐나

- 비밀번호를 아예 사용하지 않는 T08 목표에 맞으며 브라우저의 표준 WebAuthn API를 활용할 수 있다.
- 서명 검증을 직접 암호학적으로 구현하는 방식 대신 SimpleWebAuthn으로 검증 오류를 줄였다.
- 기존 T01 소개 페이지는 유지하고 비공개 자료는 서버측 인증 후에만 제공한다.
- 최초 등록은 계정 ID+패스키 이름으로 직접 진행한다. 정본에 없는 초대코드 발급 단계를 넣지 않는다.

스크린샷/요청·응답에는 세션 쿠키·토큰·비밀값을 **가려서** 남긴다(C34).

## ⑤ AI와 나

- **AI에게 맡긴 일:** WebAuthn 구현, API·DB 구조, 공개/비공개 경계 및 UI 개선 보조.
- **직접 판단한 일:** 실제 테스트 계정/기기 선택과 패스키 저장 위치 기록, 거절 응답 직접 확인, 제출 증거 최종 선택.
- **AI 제안을 따르지 않은 일:** 과제 정본에 없는 일회용 초대코드 발급 과정을 제거하고 일반 패스키 등록만 남겼다.

## ⑥ 아직 못 막은 것 (C51)

- **최초 등록 시 계정 ID 선점 위험:** 공개 등록에서는 먼저 계정 ID를 등록한 사람이 그 ID를 소유하게 된다. 실제 서비스라면 사전 신원 검증 또는 계정 초대 등이 필요하다. 이번 과제에서는 실제 개인정보 없는 가상 학습 계정을 사용한다.
- WebAuthn 등록 시 기기/운영체제/패스키 관리자 호환성은 사용 환경에 따라 달라 실제 기기 검증이 필요하다.
- 로그인 API rate limit 및 악의적 등록 요청에 대한 고급 남용 방어는 별도로 구현·검증하지 않았다.

## 제출용 짧은 확인 방법 (C52)

1. **어디로:** `https://sdy-task08.vercel.app/`에서 공개 자기소개를 확인하고 `/private.html`로 이동한다.
2. **세 단계:** 계정 ID와 이름으로 첫 패스키 등록 → 패스키 로그인 → 개인 메모 조회.
3. **통과 모습:** 자신의 비공개 메모만 나타나고, 두 패스키 중 하나를 삭제해도 남은 것으로 로그인된다.
4. **안 될 때:** 미인증 접근 401/403, 잘못된 서명/재사용 질문 거절, 마지막 패스키 삭제 제한 메시지가 나타난다.
